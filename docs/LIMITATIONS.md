# Limitations

Local source/hash/span validation proves structural evidence integrity, not factual accuracy or official precision/recall. No official score, qualification or superiority is claimed.

URL caches contain stale, shared and speculative leads. Original acquisition timestamps are partly unknown. Source file modification dates are not retrieval dates. Default publication always uses newly acquired evidence; optional HTTP cache hits retain their actual acquisition times.

TLS trust data is pinned and needs maintenance. Some sites remain unavailable because of certificate errors, network failures, robots policy, unsupported rendering or source access restrictions. Transient retry cannot guarantee availability.

Namesake and ownership gates can miss real brands. Shared registry domains need stronger proof. A public graph can contain mistakes; exact organisation identifiers and live contact corroboration reduce this risk without eliminating it.

Hiring role listings describe what was listed on the observed page. They do not assert that each underlying ad is still open. Recruiter ads describe the advertiser relationship and do not establish a direct employer. Feed entries without expiry dates remain observed advertisements; they do not establish confirmed current status. Structured direct-employer/NAV ads require supported employer identity and current dates/status. A random 100-company sample can contain no discoverable jobs.

Company publications use a 730-day window. Dated advice/product articles are labelled separately from company announcements. Missing article links, unrecognised date markup and JavaScript-only content still reduce coverage. News indexes and related-article headings are withheld.

NAV combines a bounded recent scan with original public UUID hints and optional persisted index state. It is not a guaranteed complete vacancy inventory. Cached UUIDs are always fetched and revalidated before publication.

Platform metrics, ratings, reviews and sentiment are not asserted from snippets or profile links. Annual reports are linked to filing periods; no PDF/OCR/model extraction is required. Browser rendering and paid discovery remain optional.

The cause of the original official submission failure remains unknown without organiser diagnostics. This release has not been officially evaluated. Local historical research and run folders are excluded from the source archive; Git history is preserved.

During the version 2.7 live check, the DuckDuckGo API host returned `Disallow: /` in robots.txt, so queries were withheld. The adapter supports the infobox Website field but cannot guarantee usable live access.

A registry-listed group domain does not by itself establish that the exact registered subsidiary owns the site or published its group-wide news. That ambiguity remains explicit even when another source publishes the group URL.

Temporary Windows output-replacement denials receive bounded retries. A persistent filesystem denial still fails visibly while preserving the previous completed checkpoint; it cannot guarantee successful writes to an inaccessible directory.
